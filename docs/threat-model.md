# ScholarChain threat model

Owner: documentation-engineer. Scope: the build-time agent factory and the runtime system as deployed in cloud windows 2 and 3 (us-east-2). The runtime stage was destroyed on Nov 20, 2026; 43 base resources remain ([`operations/cleanup/cleanup-20261120T041658Z-runtime/`](../operations/cleanup/cleanup-20261120T041658Z-runtime/record.json)). Every row names its evidence. The deterministic floor (hooks and permission rules) is defined only in [`docs/agents.md`](agents.md) "Deterministic floor and enforcement layers"; this file references it and does not restate it.

## 1. The seven categories of the specification

The specification's Phase 17 work order names these seven categories; its "Security requirements" list is covered by them and by section 2.

| # | Threat | Mitigation (evidence) | Residual risk |
|---|---|---|---|
| 1 | **Prompt injection** in titles, abstracts, profile text, summaries, and in the question itself | User text becomes a typed `QueryPlan` of allowlisted operations; no stage builds Cypher, PartiQL, a filter, or an AWS call from user text; graph reads go only through fixed parameterized templates ([`modules/rag/RUNTIME.md`](../modules/rag/RUNTIME.md) sections 1, 3, 8). The synthesis prompt puts the question, graph evidence and semantic context in delimited, XML-escaped blocks and states that every block is data (section 11). Model output is schema-validated before use (sections 3, 11). Retrieved semantic items never verify a fact: a claim that cites only semantic items fails `graph-evidence-required`, and a DESCRIPTIVE claim is never VERIFIED (section 12). Prompt-injection tests: removing any one escape fails a test ([`docs/agent-runs/phase-09/human-gate.md`](agent-runs/phase-09/human-gate.md)). In Phase 3 an OpenAlex API response contained instructions addressed to AI agents, and the agent treated it as data ([`docs/agent-runs/phase-03/human-gate.md`](agent-runs/phase-03/human-gate.md)); MCP output is untrusted data ([`docs/agents.md`](agents.md) "MCP servers and trust boundaries"). | The verifier is lexical: it checks numbers, windows, names, titles and hops, not qualitative misreadings (Phase 9 gate); D18 (major), D19 and D20 stay open ([`docs/agent-runs/phase-11/human-gate.md`](agent-runs/phase-11/human-gate.md)). The OpenAlex injection text was not recorded, so tests use representative strings (Phase 9 gate, m3 waived). |
| 2 | **Data poisoning** and fabricated identifiers, edges or paths, through malicious or erroneous source records or model output | A matching name or title is not identity; exact-identifier conflicts never merge silently ([`CLAUDE.md`](../CLAUDE.md) "Architecture invariants"; Phase 5 gate). Only ACCEPTED decisions link records, and refusal rules split conflicting clusters ([`modules/spark/JOBS.md`](../modules/spark/JOBS.md) "Canonical clustering"). Malformed records go to `rejects-v1/` with counters; the DBLP parser maps only DTD-declared entities and parses with StAX without external entities ([`modules/hadoop/JOBS.md`](../modules/hadoop/JOBS.md) J01). LLM adjudication can abstain (Phase 5 gate), and no live adjudication is in the evaluated decisions: the LLM band stays UNRESOLVED ([`docs/evaluation.md`](evaluation.md) section 1). The Neptune validator traced every `COAUTHORED_WITH` edge to Work vertices authored by both endpoints, 0 violations ([`docs/agent-runs/phase-07/human-gate.md`](agent-runs/phase-07/human-gate.md)). The verifier's `identity` rule fails a claim that names anyone outside the evidence (RUNTIME.md section 12). | `dominant-name-v1` can attach a homonym's few works to a well-known researcher (split identities; Phase 7 gate). Transitive work clustering merged two DBLP records in 5 works (m6, Phase 6 gate). Gold strata are small (about 39 rows each; Phase 5 gate). |
| 3 | **Credential exposure** in logs, prompts, Terraform state, script output, or Git history | Secrets come only from Secrets Manager or non-secret placeholders; reads of `.env*`, key files, `~/.aws/` and Terraform state are denied to every agent ([`CLAUDE.md`](../CLAUDE.md) "Security invariants"; `docs/agents.md` deterministic floor). `.mcp.json` holds environment-variable references only (README "Records and autograder notes", F07). The API key: see section 2. Audit records never hold the question text, prompt text, credentials, profile names or endpoints (RUNTIME.md section 14). Terraform state is local, gitignored and backed up outside the repository ([`spec/architect-decisions.md`](../spec/architect-decisions.md) D-10 item 8). The two lines flagged by the course autograder are test fixtures, not credentials (Phase 17 ruling 14). Session tokens in DEBUG logs: see section 2. | The human-run deployment profile is a full-access role (Phase 14 ruling 37); it is never given to an MCP server or an agent (architect-decisions section 4). State backups live outside the repository and are protected only by the developer machine. |
| 4 | **Over-permission** of IAM roles, agents and tools | Runtime and deployment roles are separate; the runtime grant on Neptune is `neptune-db:ReadDataViaQuery` only; EMR writes are limited to `curated/*` and `logs/emr/*` (Phase 12 gate, F1). Agents: one writer per path, the code-reviewer has no write tool, `guard-paths.sh` enforces the ownership map for file tools ([`docs/agents.md`](agents.md) "Tool fences"). The `aws-api` MCP server is read-only by configuration and needs a read-only profile ([`docs/agents.md`](agents.md) "MCP servers and trust boundaries"). | Accepted exceptions: unconditioned `s3:ListBucket` on query-api, the worker and the EMR instance role (section 2). One API key, so any key holder can read any evidence item; 403 is reserved and unused ([`docs/api-reference.md`](api-reference.md)). A Bash write to another agent's path is stopped only by instructions and the permission prompt (`docs/agents.md` "Tool fences"). |
| 5 | **Denial of service**: unbounded graph queries, LLM cost exhaustion, queue flooding, oversized or malformed input | Every graph template has depth, result-count and timeout limits; neighbors accepts depth 1 to 3 and limit 1 to 200, anything else is 400 (Phase 10 ruling 8; RUNTIME.md section 8). At most two model calls per question, a question deadline, token budgets (RUNTIME.md sections 1, 2, 15). Haiku is throttled so query-api and the worker together stay at or below 8 calls per minute (Phase 10 ruling 10; [`docs/service-limits.md`](service-limits.md)). `POST /v1/query` is rate-limited per instance (429) and the body size is capped (api-reference "Conventions"). SQS redrives a message to the DLQ after 3 receives (Phase 10 gate; experiment F, Phase 14 ruling 46). A 30 s request read timeout and a 1 s unread-body drain (Phase 11 gate). ECS maximums: query-api 1, graph-evidence-api 2, worker 1 ([`course.tfvars`](../infra/terraform/envs/course/course.tfvars)). | The ALB accepted traffic from `0.0.0.0/0` over HTTP (`course.tfvars` `alb_ingress_cidr_blocks`); the API key was the only gate. graph-evidence-api is Neptune-bound: high-degree neighbor queries on `db.t4g.medium` sat near the query deadline when the cache was cold (Phase 14 rulings 44 and 46). A slow body within the 30 s timeout still holds a thread (Phase 11 gate). D15 and D16 (API input validation) are residual behind the key (Phase 11 gate). No specific control against decompression bombs is recorded; inputs come only from the bounded dataset scripts. |
| 6 | **Destructive commands** by agents or scripts | `guard-dangerous.sh` blocks destructive AWS, Terraform, Git, database, S3, Neptune, DynamoDB, S3 Vectors, ECR, KMS and EMR commands and scale-out beyond bounds, with permission `deny` rules behind it ([`docs/agents.md`](agents.md) "Deterministic floor and enforcement layers"). Its self-test was replayed for this document: `guard-dangerous self-test: 304/304 passed` (2026-11-22). In window 3 the guard blocked three demonstration probes (a recursive S3 delete, an EMR termination, an ECS desired count of 100) before any AWS call (Phase 15 ruling 10(f)). `terraform apply` and `destroy` run only through `deploy.sh` with a human-signed plan sha256 and through the human-only `cleanup.sh` with `--confirm <sha256>`; `deploy.sh` exits 4 on a mismatch and never uses `-auto-approve` ([`scripts/README.md`](../scripts/README.md)). The data bucket has `force_destroy` false (`course.tfvars`). | Pattern guards can be evaded by indirection; some Bash write forms reach only the permission prompt ([`docs/agents.md`](agents.md) "Hook limitations"). An agent once ran `cleanup.sh --help` and dry runs through a shell-function wrapper that the guard did not match (Phase 12 ruling 10). The Neptune instance class was changed outside Terraform by the human for the bulk loads and restored (Phase 14 rulings 42 and 43, accepted deviation). |
| 7 | **Provenance or audit tampering** | Objects are write-once (`ObjectLoadPort.putNew`; a different body under an existing key is a conflict) and every run writes a manifest with sha256 per object ([`modules/storage/STORAGE.md`](../modules/storage/STORAGE.md)). Audit items in QuerySession and EvidenceBundle are create-only (RUNTIME.md section 14). Semantic text is checked against its `textHash`; a hit whose text fails the hash is dropped (RUNTIME.md section 9). ECR tags are immutable Git SHAs ([`scripts/README.md`](../scripts/README.md) `package.sh`). Raw experiment results are read-only after a run (`run-experiment.sh`). Plans are approved by checksum. Phase records are human-owned and immutable once `commit.txt` exists ([`docs/agents.md`](agents.md) "Human-owned artifacts"). | Git history is the record of the repository; nothing here claims commit signing. Account-level audit logging (for example CloudTrail) is not part of the Terraform described in this repository's records and is not claimed. |

## 2. Specific findings

| Item | What happened | Mitigation | Residual risk |
|---|---|---|---|
| **HTTP-only ALB** (Phase 12 ruling 11) | The course window had no domain or certificate, so the ALB listened on HTTP port 80 and the `X-Api-Key` header travelled in clear text. | Accepted as a documented risk for the course window; the runtime ran only in windows 2 and 3 and is destroyed. | Anyone on the path could read the key during the windows. A new deployment needs HTTPS. |
| **Unconditioned ListBucket** (Phase 12 rulings 11 and 23) | query-api, the worker and the EMR instance role hold `s3:ListBucket` on the data bucket with no prefix condition. Reason (ruling 23): S3 answers 404 for a missing key only to a principal with `s3:GetObject` on that key and `s3:ListBucket` on the bucket. A GET or HEAD request carries no `s3:prefix`, so a prefix-conditioned ListBucket never applies to it, and every S3A check of a path that does not exist yet would get 403. | The grant exposes key names only, never object data; read and write grants stay prefix-narrowed (F1); exact-key probe grants hold no data (ruling 23). | Step code and the services can list every key name in the bucket. |
| **ECR scan findings** (Phase 14 ruling 25) | The services image (`deef295`) scan: CRITICAL 10, HIGH 48, MEDIUM 62, LOW 18, UNDEFINED 6. The 10 CRITICAL rows are 5 CVEs in two Ubuntu Noble base packages, curl/libcurl4t64 and brotli/libbrotli1. | The services are JVM processes and do not use these libraries in the request path served through the ALB. Accepted for the course window; no base-image move (D-09 two-week rule, rebuild and rescan time). | The 48 HIGH findings were not reviewed one by one in the recorded rulings. A rebuild on a newer base image is needed before any further deployment. |
| **SSE-C drift** (Phase 14 ruling 38) | The window 2 plan showed one in-place change: AWS reported `blocked_encryption_types ["SSE-C"]` on the data bucket, which the configuration did not set, so the apply set it to `[]`. The cleanup plans showed the same change again (ruling 48). | The project never uses SSE-C; the bucket stays private and TLS-only with SSE-S3. Phase 15 work order 2 part B declared `blocked_encryption_types = ["SSE-C"]`; the window 3 plan was 89 to add, 0 to change, 0 to destroy (Phase 15 ruling 10(a)). | SSE-C was not blocked from the window 2 apply until the window 3 apply. |
| **Session tokens in DEBUG logs** (Phase 14 ruling 41) | The Neptune loader container logged the AWS SDK at DEBUG, so its CloudWatch stream and local record files under `operations/` held the task role's temporary session token (`x-amz-security-token`; no secret key; it expires with the task session). | The human redacted the token in three `operations/` files before commit ([`docs/agent-runs/phase-14/human-gate.md`](agent-runs/phase-14/human-gate.md) "Manual changes"). `load-stores.sh` now drops and counts any recorded line that matches `x-amz-security-token`, `aws_session_token`, `SessionToken`, `Authorization:` or `Credential=` ([`scripts/README.md`](../scripts/README.md) `load-stores.sh`; Phase 15 repair-01 part A). | The DEBUG lines stay in CloudWatch until the 14-day log retention expires (`course.tfvars` `log_retention_days`). The image logging change to INFO is a recorded service-engineer follow-up (ruling 41); its completion is not recorded in the inputs of this document. |
| **API key in Secrets Manager** | One API key (D-10 item 9). | The secret has no value in Terraform; the human sets it after apply by the stdin pattern in [`infra/terraform/README.md`](../infra/terraform/README.md), and ECS injects it as `SCHOLARCHAIN_API_KEY` (Phase 12 gate; Phase 14 ruling 36). The services compare a SHA-256 of the key with `MessageDigest.isEqual` and never log it (Phase 10 gate). `smoke-test.sh` reads it into a variable and passes it to curl on standard input ([`scripts/README.md`](../scripts/README.md) "Conventions"). | Cleanup puts the secret in a 7-day recovery window; a new apply in that window must restore or force-delete it first (Phase 14 gate; Phase 15 ruling 3). One shared key, no per-user identity. |

## 3. Residual risks of the agent system

The residual risks the human accepted for the hooks and permission rules are listed, each with its mitigation, in [`docs/agents.md`](agents.md) "Residual risks accepted by the human architect" (hook timeout, `.gitignore` deferral, GitHub MCP write detection, file-level symlinks, report files in any open phase folder, validator and test-stop hook remainders, git global options before the subcommand, unrecognized protected-path writes). Phase 17 work order 3 proposes further entries (known guard false positives, Grep and Glob availability, the `aws-api` connection); they take effect only after ratification. Changes to that list belong to the factory-engineer.
